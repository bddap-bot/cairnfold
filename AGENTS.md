# Working on Nestcombe

Read [docs/design.md](docs/design.md) first; it holds the element inventory, the
controls and the build order.

- Clean room: never use, inspect or derive anything from Tiny Glade's files.
  Public talks and store material may inform the feel; every asset is generated
  here or authored for this project.
- Holding the headset's refresh rate at worst-case density is a hard, standing
  requirement: see "Frame budget" in the design document. Run `scripts/bench.sh` on
  a Quest before landing anything that adds cost, add new pieces to
  `demo/stress.json`, and keep every budget number in `game/src/budget.gd`. Desktop
  renders do not establish frame rate.
- Audio in `game/audio/` is generated by `scripts/compose.py`; change the script and
  regenerate, keep timbres soft (see "Sound" in the design document).
- Generators stay pure data (like `WallLayout`), tested headless in `tests/`.
- Delete comments that restate code; keep only a why the code cannot show.
- Edit by subtraction: fix problems by removing code where possible, one
  implementation per thing.
- `nix-shell --run scripts/test.sh` must pass before landing; a change to the build
  scripts, `game/project.godot` or `game/export_presets.cfg` also owes a
  green `scripts/android.sh quest` and `scripts/android.sh lepton` under `nix-shell android.nix`.
- Deploying main is `scripts/release.sh`, which publishes the Windows, Linux and
  Frame exports and both APKs together; the Frame's install and library shortcut are kept outside
  this repo (README, "Running").
- Every edit to the garden is a build command applied by `World` (docs/multiplayer.md): a tool never
  changes the garden itself, only shows its ghost until the command comes back. After touching
  `World`, `Commands` or a tool, `nix-shell --run 'scripts/coop.sh out'` must pass too.
